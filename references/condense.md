# 从 300 行到 30 行：压缩算法

## 核心比例

一次真实的一周：约 200–600 条会话消息 + 100+ 条本人消息 + 若干交付物。
产出：5 章 × ≤5 条 ≈ 20 条，1200 字以内（目标 800）。

压缩比大约 **20:1**。凡是压缩比低于 10:1 的稿子，基本都还在记流水账。

## 四把刀

### 刀 1：删归属

把所有「他人完成」「纯知晓」「与我无关」的行整行删除。
**这一步通常能删掉 40%。**

### 刀 2：删过程

删掉所有以这些词开头的分句：

> 我看了… / 我查了… / 我搜了… / 我配了… / 我整理了资料… / 我和 X 聊了…

除非它后面跟着一个决定或一个交付物。改成：

- ❌ 我查了竞品并整理了对照表
- ✅ 定了对标 X 的页面结构，砍掉评论与分享（本期不做）

### 刀 3：合并同源

一件事无论出现在几个地方，只留一条。合并时保留**最强的结果**，而不是最早的动因。

- ❌ 开会讨论首页结构 / 改了原型 / 写了 PRD / 和设计对齐了字段
- ✅ 首页结构会定下「不拆电商页、首屏改导流试用」；原型已按此重排，PRD 未成稿

### 刀 4：砍到形状

- 超过 5 章 → 合并最弱的两章
- 单章超过 5 条 → 删最弱的（通常是那个「也做了但没结果」的）
- 正文超过 1200 字 → 逐条砍形容词和背景铺垫，不砍动词和数字

## 句式库（照着换词就行）

| 场景 | 句式 |
|---|---|
| 完成交付 | `完成 X，产出 Y，已交付/已上线` |
| 推动他人 | `提出/推动 X，Y 已进入开发/设计` |
| 决策 | `定了 X：因为 Y，所以 Z` |
| 开会 | `X 会定下 Y 方向，下一步是 Z` |
| 摸底 | `梳理了 X 的现状与问题，结论是 Y` |
| 卡住 | `X 卡在 Y，需要 Z 才能往下` |
| 未完成 | `X 进行中，Y 还没定，下周处理 Z` |
| 量化 | `X 从 A 提升到 B（口径：C）` |

## 语言红线

- 禁词：赋能、闭环、抓手、联动、全方位、持续推进、深度、生态位、形成了体系。
- 禁句：「总的来说」「综上所述」「希望对你有所帮助」「后续会持续关注」。
- 禁结构：超过 5 项的并列长列表、三级以上的小标题、表格里超过 4 列。
- 数字只在三种情况下保留：说明**规模**（52 张图）、**结果**（可用率 80%→96%）、**风险**（成本超预算 3 倍）。其余数字是噪音。

## 一句话检验

删完之后，随机抽一条念出来，问自己：**读完这句，我知道你干成了什么吗？**
不知道就重写，不要加解释。
