# 三种交付形态

## 形态 A：正文版（默认，贴文档/聊天）

```markdown
# 周报（YYYY.MM.DD – MM.DD）

## 一、本周工作内容

### 1. 项目名
- 动作 + 结果/状态。
- 当前阶段与卡点。

### 2. 项目名
- …

## 二、下周工作内容
1. 由本周遗留事项推导出的下一步。
2. 已明确的交付物。
```

要求：3–5 章、每章 ≤5 条、正文 ≤800 字。

## 形态 B：汇报系统字段版

多数公司周报系统是固定字段，按字段拆，每字段 ≤2 行：

```markdown
【本周业绩】
1. 项目 A：完成 X，产出 Y，当前处于 Z。
2. 项目 B：推动 X 进入评审。

【下周计划】
1. …
2. …

【风险与需支持】
- X 卡在 Y，需要 Z 决策/资源。

【其他】
（没有就写「无」，不要留着空）
```

注意：字段版**不需要**写背景——字段本身就限定了长度，写背景会挤掉结果。

## 形态 C：口头 30 秒版

只三句，用于站会、电梯里、电话里：

1. **做成了什么**：本周最硬的一个结果（带数字或交付物）。
2. **卡在哪**：一个具体的阻塞点。
3. **要什么**：一个明确的决策或资源请求。

示例：

> 首页那版结构定了，会开完原型在改，PRD 还没成稿；卡在安装门槛，需要拍一下要不要做桌面版；下周想把 PRD 定稿并拉运营参会。

## 选型建议

| 场景 | 用哪个 |
|---|---|
| 发给直属领导 / 团队群 | A |
| 公司周报系统 / OKR 复盘 | B |
| 站会、口头汇报、跨部门同步 | C |
| 给老板看但没时间读 | A 的前两句 + C |
